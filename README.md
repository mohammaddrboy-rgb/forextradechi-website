# forextradechi.com — مکتب فارکس (Maktab Forex)

Static **bilingual** website — **English (primary, LTR)** and **Farsi/Dari (secondary, RTL)**.
No framework, no build step — plain HTML/CSS/JS. Based on `forextradechi-website-brief.md`
(the brief specified Dari-only; bilingual English-primary was a later requirement).

## Bilingual system
- Default language is **English** (`<html lang="en" dir="ltr">`). An inline `<head>` script
  applies the saved language before first paint (no flash).
- Every string exists twice: `<span class="lang-en">…</span><span class="lang-fa">…</span>`.
  CSS (`html[lang="en"] .lang-fa`, `html[lang="fa"] .lang-en`) hides the inactive one.
- The `.lang-toggle` button in the nav flips `lang`/`dir`, swaps the `<title>`
  (from `data-title-en` / `data-title-fa` on `<html>`), and saves the choice to
  `localStorage` (`mf-lang`). Layout mirrors automatically because the CSS uses logical
  properties.

## Bilingual SEO — the `/fa/` mirror (IMPORTANT for editing)
The site has **two indexable URL trees**: English at the root (`/index.html`, `/courses.html`, …)
and Farsi under **`/fa/`** (`/fa/index.html`, …). Each page carries `hreflang` alternates
(en / fa / x-default), a self-canonical, and per-language `<title>`/description. Language is
decided by the URL (`/fa/…` = Farsi), and the nav's language button **navigates** between the
pair. This is what lets Dari searches find the Farsi pages.

**The English root pages are the single source of truth. The `/fa/` folder is GENERATED —
never edit it by hand.** After ANY change to an English page, regenerate:

```bash
python build-fa.py
```

That rebuilds every `/fa/` page, injects hreflang into the English pages, and regenerates
`sitemap.xml`. (Farsi meta descriptions live in the `FA_DESC` dict inside `build-fa.py`.)

**Full workflow after editing:** edit the English page(s) → `python normalize.py` *(only if you
changed nav/footer)* → `python bump-assets.py` *(only if you changed CSS/JS)* → `python build-fa.py`
*(always)*.

## Updating assets (cache-busting)
`global.css` and `site.js` are referenced with a `?v=…` version so browsers fetch the newest
copy after a deploy. **After editing the CSS or JS, run this before deploying:**

```bash
python bump-assets.py
```

It stamps a fresh version (today's date) onto every page. Without it, returning visitors can
see an old cached stylesheet/script.

Also present: `site.webmanifest` + `icon-192/512.png` (add-to-home-screen / PWA), and a
`theme-color` meta on every page.

## Local preview
Root-absolute paths (`/assets/...`) need a web server — don't open with `file://`:

```bash
cd forextradechi-website
python -m http.server 8080
```

Then visit http://127.0.0.1:8080/ . On the real host, the document root is this folder and SSL/`/` routing are handled by the provider.
